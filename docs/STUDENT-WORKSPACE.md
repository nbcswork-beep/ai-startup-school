# Student OS: рабочее пространство ученика

Редизайн существующего Telegram Mini App. Дата проверки: 8 октября 2026.

Работа выполнена в `nbcswork-beep/ai-startup-school`. Основа — `feat/group-management-sessions` на коммите `2634d91`, который содержит общие учебные данные и подтверждение этапов преподавателем. Эти изменения уже представлены в [PR #1](https://github.com/nbcswork-beep/ai-startup-school/pull/1). Редизайн оформляется отдельным зависимым PR; перед выпуском нужно принять эту основу. Репозиторий маркетингового сайта `AI-Startup-School-site-2` не изменялся.

## Основания аудита

Использованы пять предоставленных пользователем скриншотов: Home, Learning, Project, Portfolio, Profile. Проверены исходный интерфейс, обработчики действий, Student API, общий runtime, Teacher/Admin API и тесты. Скриншоты показывают широкую версию Mini App; они не доказывают поведение мобильной клавиатуры или Telegram safe areas. Приватные скриншоты ученика не добавлены в GitHub.

| Наблюдение | Основание | Изменение |
| --- | --- | --- |
| На Home большой слоган и иллюстрация предшествуют текущему проекту; XP и серия конкурируют с действием | Скриншот Home, старый шаблон `home()` | Проект, этап, прогресс и следующий шаг собраны в первый блок |
| Большие заголовки, сетка, орбиты и пустые поверхности затрудняют чтение задач | Все пять скриншотов, исходные CSS | Спокойный фон, компактная типографика, разные поверхности для разных задач |
| Форма этапа проекта находится ниже большой обзорной композиции | Скриншот Project, исходный шаблон | Понятное действие «Продовжити проєкт» открывает и фокусирует текущую форму |
| Портфолио показывает «завершено» для результата, связанный проект которого ещё в работе | Скриншоты Project/Portfolio, исходный шаблон | Статус связанного проекта имеет приоритет над старой датой записи |
| Профиль подчёркивает уровни и серию; шкалы навыков не рассчитываются по результатам ученика | Скриншот Profile, `getPortfolio()` | Убраны уровни, серия и фиксированные шкалы; XP оставлен вторичным |

## 1. Старая навигация

В выбранной существующей версии уже есть пять пунктов: «Головна», «Навчання», «Проєкт», «Портфоліо», «Профіль». Дополнительно код поддерживал отдельный маршрут `#ai` и запускал создание/загрузку AI-разговора при открытии приложения.

## 2. Новая навигация

Те же пять пунктов, с прежними понятными иконками. Урок и домашняя работа относятся к «Навчання», этот пункт остаётся выделенным внутри них. Внутренние страницы поддерживают Telegram BackButton. Старый `#ai` ведёт на Home.

## 3. Самостоятельный AI

Убраны отдельный экран общего чата и обязательный запуск разговора при входе. AI API, сервисы, разговоры и история сохранены. Их удаление не требуется для упрощения интерфейса. Сейчас используется mock AI provider, а полноценной помощи с контекстом задания нет. Новый AI backend и кнопки, обещающие несуществующую помощь, не добавлены. Представления выделены в отдельный модуль, куда позже можно подключить реальное контекстное действие.

## 4. Home

Первый блок: имя из авторизованных данных → реальный проект → этап → подтверждённый прогресс → следующий шаг → одна основная кнопка. При отсутствии проекта предлагается создание. При проверке показывается ожидание преподавателя; при возврате — реальный комментарий; после завершения — переход к портфолио.

Ниже: ближайшее действующее занятие, активная домашняя работа, новый отзыв только при наличии непрочитанного уведомления с доступным заданием. Повторный большой блок проекта и игровые показатели убраны. Данные примера из задания не использованы.

## 5. Learning

Ближайшее занятие или доступный урок имеет приоритет. Оставлены занятия, их история, материалы, домашняя практика и помощь с пропущенным. Отдельно показаны состояние занятия и факт учебного подтверждения: проведение занятия само по себе не означает зачисление урока.

Используются существующие `scheduled`, `rescheduled`, `in_progress`, `completed`, `cancelled`, `archived`. Отменённое занятие не становится следующим и не получает активную кнопку урока. Будущие отменённые занятия, которые API исключает из расписания, не восстанавливаются искусственно; уведомления о них остаются доступными.

## 6. Homework

Состояния соответствуют `not_started`, `in_progress`, `submitted`, `needs_revision`, `completed`. Не добавлено состояние «в работе» только от открытия страницы. После отправки повторная сдача скрыта. При доработке показаны комментарий, оценка и предыдущая версия ответа. Проверенная работа сохраняет доступ к ответу и отзыву.

Выводятся материалы преподавателя и связь с занятием по ID, а не по совпадению заголовка. Снятое с публикации задание исчезает из активных списков. Если оно было открыто, отправка блокируется, а набранный текст остаётся видимым до ухода со страницы. Несуществующая ссылка на задание не открывает вместо него первое доступное задание.

## 7. Project

Одна модель выбора проекта используется на Home и Project: активный, затем завершённый; архив не выдаётся за текущую работу. Сохранены название, описание, четыре реальные стадии, ответы, версии, комментарии преподавателя, заметки, ссылки и рабочий URL.

Прогресс — сумма весов подтверждённых задач: `35 + 25 + 25 + 15`. Ожидание проверки не увеличивает процент. Если веса или серверный процент не согласованы, интерфейс показывает количество этапов вместо выдуманного процента. Следующий этап открывает существующий Teacher API. Кнопка продолжения раскрывает текущую форму; одновременно две основные кнопки не показываются.

## 8. Portfolio

Представляет результаты, а не копию текущей работы. Старые записи и рефлексии сохранены. Показываются реальные обложки, скриншоты, технологии и HTTPS-ссылка, когда они существуют. Ошибка загрузки изображения получает понятный текст. Завершение проверяется по связанному проекту, а для исторической записи без доступного проекта — по существующей дате завершения.

Новая кнопка добавления доступна для завершённого проекта. Пустое портфолио сообщает, что результаты ещё появятся. Отдельного поля «тип продукта» в текущем DTO нет: интерфейс его не придумывает. Фиксированные шкалы навыков убраны.

## 9. Profile

Имя, реальная группа, количество зачтённых уроков и проектов. XP — небольшой вторичный показатель. Сповіщення и запись к ментору сохранены. Профиль не собирает несвязанные новые функции.

## 10. Кнопки и статусы

Основная кнопка — жёлтая, для одного следующего действия. Вторичная — спокойная поверхность с границей. Текстовое действие — для перехода к деталям и истории. Подписи описывают результат нажатия. Статусы включают текст и символ, а не только цвет. В состояниях ожидания не появляется лишняя кнопка сдачи.

## 11. XP

В общем runtime XP хранится по ID ученика. Существующие события начисляют награду при подтверждении урока или этапа проекта; защита от повторного начисления остаётся. Оценка домашней работы сама по себе XP не начисляет, поэтому обещание награды за её проверку убрано. Teacher/Admin и уровни используют эти данные. Ничего из истории XP не удалено. На Home, Learning, Project и Homework XP не конкурирует с работой; в Profile оставлен реальный показатель.

## 12. Серия

Поле streak сохранено в хранилище. Из Student UI оно убрано. Текущая логика не является полноценной ежедневной серией: подтверждение урока устанавливает минимальное значение. Новая механика входов или ежедневных наград не добавлена.

## 13. Уровни

Explorer / Maker / Builder / Creator / Launcher вычисляются из порогов XP `0 / 200 / 400 / 600 / 900`. Образовательных полномочий эти уровни не дают. Уровень и гонка к следующему порогу убраны из Student UI; расчёты, Teacher/Admin и накопленная история сохранены.

## 14. Достижения

Сохранены все старые определения и награды в данных. В Profile показывается только существующий Builder, если в доступном проекте есть минимум два этапа с реальным подтверждением преподавателя. Подпись объясняет именно это действие. Старый значок без подтверждающих данных не получает ложного нового смысла.

First Spark относится к уроку, AI Explorer — к общему AI-чату, для Demo Day нет подтверждённого события выдачи. Они скрыты. Фиксированная дата выдачи из старого DTO не выводится. Новая система достижений не построена.

## 15. Совместимость данных и backend

Сохранены Vite, обычные JS-модули, Fastify/TypeScript, существующая Telegram-аутентификация и общий PilotRuntimeStore. Рабочая версия MemoryRepository использует общий runtime с Redis в deployment; переключение на незавершённую Postgres-реализацию не выполнялось. Миграций и изменений базы нет.

DTO домашней работы расширен необязательными `classSessionId` и `resources`. Это уже существующие данные Teacher OS, а не новая отдельная модель. Старые записи без материалов возвращают пустой массив. Остальные API и роли совместимы.

Изменение shared sync повторно проверяет возможность обновления после получения revision и повторяет отложенное обновление. Это сохраняет набранный текст и не заменяет форму в процессе отправки или загрузки урока. Другие клиенты, возвращающие обычный `undefined` из refresh, продолжают работать. Учебные статусы не хранятся в localStorage.

## 16. Mobile, загрузка и ошибки

Компактные заголовки, перенос длинного украинского текста, кнопки минимум 48 px, раскрывающиеся строки минимум 44 px, поля 16 px. Существующие нижняя навигация и отступ под неё сохранены. Учтены также боковые Telegram/device safe areas. Настройка reduced motion поддерживается CSS; действий только по наведению нет. Фирменные Inter/Unbounded, navy, yellow и cyan сохранены, декоративные орбиты и сетка скрыты.

Запросы ограничены по времени; загрузка имеет `aria-busy`, ошибка — повторное действие, потеря сети — сообщение с последними полученными данными. Фоновое обновление сохраняет введённые тексты, фокус, раскрытые ответы и прокрутку, пока идентификатор и версия формы не изменились.

**Граница проверки:** автоматические проверки моделей и представлений выполнены; TypeScript и production-сборка проходят. Встроенный браузер не смог подключиться к локальному серверу; открытие локального HTML запрещено его политикой. Поэтому визуальные измерения 360×800, 390×844, 430×932 и планшета, клавиатура и реальные safe areas Telegram ещё не подтверждены. Перед выпуском требуется проверка этих размеров на Preview внутри Telegram. Изменение остаётся draft PR. Production не развёрнут.

База Postgres и реальные Telegram-клиенты не тестировались в этом прогоне.

## 18. Решения владельца продукта перед выпуском

1. Принять зависимую основу из PR #1 и проверить этот draft PR в Telegram Preview на трёх размерах телефона и планшете. Production требует отдельного решения о выпуске.
2. Решить, нужны ли уровни, серия и не подтверждённые действиями старые достижения в будущем. Данные сохранены, новая экономика не придумана.
3. Если нужна контекстная AI-помощь, определить рабочий provider и передачу контекста задания. Сейчас интерфейс не обещает несуществующий сервис.
4. Если нужны тип продукта, редактирование медиа портфолио и точные даты выдачи достижений, согласовать соответствующие реальные поля и события отдельно.

Для подготовки этого PR дополнительное продуктовое согласование не требовалось. Слияние, миграция данных и Production-deploy не выполнялись.
